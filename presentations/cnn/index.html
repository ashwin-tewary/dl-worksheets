BEFORE YOU START

What a convolution is for

A fully connected layer treats every pixel as a separate feature and learns a different weight for every pair of positions. That wastes parameters and throws away the fact that a cat’s ear looks the same in the top-left as in the bottom-right. A convolution uses a small shared kernel (also called a filter) and slides it across the image.

Kernel K

A k × k array of weights. Typical teaching sizes are 3×3 and 5×5. AlexNet’s first layer used 11×11.

Geometry

S is stride, the hop in pixels. P is padding, zeros (or a repeat of the border) added around the input.

Output size

Hout = ⌊(H + 2P − K)/S⌋ + 1. The same formula applies independently to width.

Model assumptions. The labs use small integer images and fixed kernels so every number is checkable by hand. Real networks learn the kernels. Unless a control says otherwise, there is one input channel and one output channel, and no bias.

How to use this sheet. Read one section at a time. Type answers into the boxes and press Check; open Show answer only after that. Each part has a live grid. Nothing is scored.

01
FILTERS / KERNELS

A small template.
A sliding inner product.

Complete ✓
IN ONE MINUTE

At each location the kernel is laid on a patch of the same size. Multiply aligned entries and add. That scalar is one output pixel. Then the kernel moves and the same weights are used again. The detector is shared; only the patch changes.

zij = Σuv Kuv xi+u, j+vOne output cell · valid placement · one input channel

Read the sum. The indices u, v run over the kernel. i, j choose where the top-left of the kernel sits on the input. Every output cell uses the same K. If you had a different K at every location you would have rebuilt a fully connected layer on patches, and you would have lost translation sharing. A bias b, when present, is added after the sum and is also shared across space.

1.1Why share the weights?

Suppose a 32×32 image and a 3×3 kernel. A fully connected layer from all 1024 pixels to a 30×30 map would use 1024 × 900 weights. The convolution uses 9. The 9 are reused at every one of the 900 placements.

Key idea

Weight sharing is not a trick for speed only. It is the claim that the world is stationary: the same pattern is legal everywhere.

Patch and kernel below. Compute each row’s contribution, then the total. This is exactly one output pixel.

THEORY · BEFORE THE VISUALIZATION

Three things to separate

  1. The arithmetic

    Each placement is an inner product. If you can do one by hand, you can do the layer.

  2. The sharing

    The kernel does not change as it moves. Different output cells are different patches, not different detectors.

  3. The meaning

    Learned kernels become texture and part detectors. The presets here are the classical ones, so you can predict the map.

WORKED EXAMPLE

On a 7×7 input with a 3×3 kernel, stride 1 and no padding, there are 5×5 = 25 placements. Each uses the same nine weights. The lab highlights one placement at a time and writes the inner product on the output grid.

Predict before you play: Will the vertical-edge kernel fire in the middle of the left-hand block of 1s?

No. Inside a constant block every 3×3 of 1s gives 1+1+1 − (1+1+1) = 0. The kernel fires at the light-to-dark transition.

WHAT TO LOOK FOR

Switch to edge x. The coral window should light up only at the boundary. Identity should copy the bright blob of 1s, trimmed by one pixel all round.

Common mistake

“Convolution in deep learning is the same as the mathematical convolution.” Libraries implement cross-correlation: they do not flip the kernel. The name stuck. For learning, an unflipped kernel is simply a different parameterisation.

02
STRIDE

How far the
template hops.

Complete ✓
IN ONE MINUTE

Stride S = 1 visits every legal placement. S = 2 skips every other origin, so the output is about half as tall and half as wide. Stride is downsampling by skipping, not by pooling.

Hout = ⌊(H + 2P − K)/S⌋ + 1Integer division · independent of the kernel values

Read the hop. Increasing S makes the output smaller and makes each output cell look at a patch whose top-left is farther from its neighbours. The receptive-field jump (Part 6) is multiplied by S. A large stride in the first layer, as in AlexNet, is a deliberate decision to throw away fine spatial grid while keeping a large field of view.

2.1Count the placements

H = 7, K = 3, P = 0. The last legal top-left row index is 7 − 3 = 4, so stride 1 visits rows 0,1,2,3,4 — five of them.

Try it by hand

Same H = 7, K = 3, P = 0. Stride 1 gives Hout = . Stride 2 gives . Stride 3 gives .

Show answer

⌊(7 − 3)/1⌋ + 1 = 5. ⌊4/2⌋ + 1 = 3. ⌊4/3⌋ + 1 = 2. The origins for stride 2 are (0,0), (0,2), (0,4) and the three matching rows 2 and 4 — nine visits, not 25.

THEORY · BEFORE THE VISUALIZATION

Skipped origins are simply not computed

  1. Start at (0,0)

    Then add S to the row or column until the kernel would hang off the (padded) input.

  2. The formula is not optional

    If (H + 2P − K) is not divisible by S, the leftover border is unused. That is what the floor is for.

  3. Do not confuse with pooling

    Stride in a convolution still computes a learned inner product. Pooling (Part 5) summarises a patch with max or mean and has no kernel weights.

WORKED EXAMPLE

AlexNet’s first layer: H = 227, K = 11, S = 4, P = 0. Hout = ⌊(227 − 11)/4⌋ + 1 = 55. The 224-pixel convention with P = 2 gives 54 after flooring, which is why people quote both 224 and 227.

Predict before you play: If we raise stride from 1 to 2 on the 7×7 blob, does any output cell still see the peak?

Yes, if a stride-2 origin still covers the peak in its 3×3. Watch which coral windows appear — several centres are never visited.

WHAT TO LOOK FOR

The output grid should shrink as you drag stride. Count the coral visits: 25, then 9, then 4.

2D GRID / STRIDE

Fewer hops, smaller map.

Identity kernel, so the output copies each window centre

Identity makes geometry visible: you are seeing which centres were sampled.

TRY THIS

03
PADDING

Keep the border
in the conversation.

Complete ✓
IN ONE MINUTE

A valid convolution (P = 0) shrinks the map by K − 1. Same padding for odd K and stride 1 uses P = (K − 1)/2 so Hout = H. The extra cells are usually zeros.

Psame = (K − 1)/2Odd kernels, stride 1 · VGG’s default

Read the halo. Padding is not a trick to invent data. It is a decision about whether corner pixels get to be window centres. Without it, every layer eats the border and a deep stack silently crops the image. With it, spatial size stays a design choice of stride and pooling, not of kernel size. Zero padding is the default; it can create a faint “border artefact” that later layers sometimes exploit.

3.1Restore the size

Try it by hand

For H = 5, K = 3, S = 1, the P that keeps Hout = 5 is . For H = 7, K = 5, S = 1, P = . With H = 7, K = 3, S = 1, P = 0, Hout = .

Show answer

P = (3−1)/2 = 1 and (5−1)/2 = 2. Unpadded 7 with 3×3 is ⌊(7−3)/1⌋+1 = 5, which is why the identity lab without padding loses a one-pixel frame.

THEORY · BEFORE THE VISUALIZATION

Zeros around the picture

  1. Write the padded array

    A 2×2 block with P = 1 becomes 4×4, with the original numbers in the centre and zeros on the rim.

  2. Run the usual formula on the padded size

    H′ = H + 2P, then Hout = ⌊(H′ − K)/S⌋ + 1, which is the same as the compact formula.

  3. Same is a policy, not a miracle

    It holds for stride 1 and odd K. Stride 2 with “same” padding in frameworks is a slightly different rounding convention; always print the tensor shape.

WORKED EXAMPLE

Input [[1,2],[3,4]] with P = 1. The padded grid is a 4×4 of zeros with that block in the centre. A 3×3 identity then returns a 2×2 — the original image — because each original pixel can sit at a window centre.

Predict before you play: With P = 1 on the 7×7 blob, is the output 7×7 or 9×9?

7×7. Padding adds two rows, the 3×3 then removes two, and you are back to 7. You do not keep the extra halo in the output.

WHAT TO LOOK FOR

Grey-beige cells are zeros. At P = 0 the blob is cropped. At P = 1 the output size matches the input.

2D GRID / PADDING

A halo of zeros.

Identity kernel again, so size changes are the whole story

The input drawn here includes the padded zeros when P > 0.

TRY THIS

04
FEATURE MAPS

One kernel,
one channel.

Complete ✓
IN ONE MINUTE

A layer with Cout kernels produces Cout feature maps. If the input already has Cin channels, each kernel is a Cin × K × K volume. Depth of the stack is “how many detectors,” not “how deep the network is.”

#params = Cout · Cin · K · K + Cout if you count biases

Read the volume. For a colour image Cin = 3 at the first layer. After that, Cin is whatever the previous layer emitted. Doubling Cout doubles both compute and parameters. Spatial size (H, W) does not appear in the parameter count — that is the point of sharing — but it does appear in the multiply-adds, which are Hout Wout times the parameter count, before bias.

4.1Count the weights

Try it by hand

16 kernels, 3 input channels, 3×3, no bias: weights. With a bias per kernel: . VGG’s first layer, 64 kernels on RGB 3×3, no bias: .

Show answer

16 × 3 × 9 = 432, plus 16 biases = 448. 64 × 3 × 9 = 1728. A fully connected layer from 224×224×3 to 64 maps of similar size would be millions of weights; the convolution stays at 1728.

THEORY · BEFORE THE VISUALIZATION

Maps are stacked, not mixed in the drawing

  1. One detector, one plane

    Edge-x, edge-y and blur are three independent inner products. Early layers of a CNN learn similar low-level detectors, then mix them.

  2. Next layer sees the stack

    Its kernels have thickness Cin. A 3×3 “on 64 maps” is 64 × 3 × 3 = 576 weights per output channel.

  3. 1×1 convolutions

    K = 1 still mixes channels at a single location. That is a cheap learned change of C, used heavily after VGG (Network-in-Network, Inception, ResNet bottlenecks).

WORKED EXAMPLE

The lab input is 7×7. Three 3×3 kernels at stride 1, no pad, give three 5×5 maps — a 5×5×3 volume. The animation does not learn; it only shows that different kernels light up different structure in the same picture.

Predict before you play: Will the blur map look like a softer copy of the edge, or like a softer copy of the image?

A softer copy of the image. Blur averages the 3×3; it is not an edge detector. Edge-x should be quiet inside the white block and loud at the vertical jump.

WHAT TO LOOK FOR

Compare the three maps side by side. Thickness of the stack is the number of maps, not the spatial size.

2D GRID / THREE MAPS

Same image, three stories.

COMPARE

YOUR EXPERIMENT

Read the volume.

There is no extra dial here: the three kernels are the experiment. Later layers will mix these maps with thicker kernels.

REMEMBER

Cout is a design choice. VGG doubles it after most downsamples (64 → 128 → 256 → 512).

05
POOLING

Summarise,
then move on.

Complete ✓
IN ONE MINUTE

A pooling window takes max or mean over a small neighbourhood and usually hops with stride equal to its size. No weights are learned. The map gets cheaper, a little more invariant to tiny shifts, and a little vaguer about exact position.

y = max{ xwindow }   or   mean{ xwindow }Typical: 2×2, stride 2 · AlexNet used overlapping 3×3, stride 2

Read the summarise. Max pooling keeps the strongest detector response in the window and forgets where inside the window it was, up to the window size. Average pooling keeps mass instead of peaks. Neither replaces a convolution: you still need a learned kernel to decide what “strong” means. Modern nets (ResNet and after) often prefer stride-2 convolutions to explicit pooling in the main path, but the geometry is the same idea.

Show answer

THEORY · BEFORE THE VISUALIZATION

Downsample without new parameters

  1. Partition the map

    Non-overlapping 2×2 stride 2 is a partition. Overlapping 3×3 stride 2 (AlexNet) lets neighbouring windows share pixels.

  2. Reduce H and W, keep C

    Pooling is applied per feature map. You still have the same number of detectors, on a coarser grid.

  3. Invariance is local

    A 1-pixel shift that stays inside the same window can leave the max unchanged. A shift that crosses a window boundary does not. True invariance is built by stacking this with later layers, not by one pool.

WORKED EXAMPLE

Predict before you play: If we change the 8 to a 1, which max-pool cell changes?

Only the bottom-right, which becomes max(1,1,1,3)=3. The other three windows do not contain that entry.

WHAT TO LOOK FOR

Toggle max versus average. Max tracks peaks; average tracks mass. Neither redraws the 4×4 as a convolution would.

06
RECEPTIVE FIELD

What can this
unit actually see?

Complete ✓
IN ONE MINUTE

The receptive field of a unit is the input region that can affect it. After a stack of layers it is much larger than one kernel. Each layer adds (K − 1) × jump, then multiplies the jump by the stride.

RFℓ = RFℓ−1 + (Kℓ − 1) · Jℓ−1,   Jℓ = Jℓ−1 · SℓStart from RF = 1, J = 1 on the pixels

Read the growth. Jump J is the spacing, in input pixels, between adjacent units at the current layer. A stride-2 layer doubles that spacing. Padding changes which pixels exist, not the theoretical field size of a unit in the bulk. A 1×1 convolution does not grow RF at all. Pooling with K = 2, S = 2 grows RF by 1 × J and then doubles J — the same recurrence, with no learned weights.

6.1Stack 3×3s

Try it by hand

Three stride-1 3×3 layers: RF = . AlexNet’s first layer, K = 11, S = 4: RF = and jump = . After one more 3×3 stride-1: RF = .

Show answer

1+2+2+2 = 7. First layer: RF = 11, J = 4. Then RF = 11 + 2×4 = 19, J stays 4. That is why an early large stride buys field of view quickly and spends spatial precision.

THEORY · BEFORE THE VISUALIZATION

Field of view is designed, not accidental

  1. One 7×7 versus three 3×3

    Both have RF = 7 at stride 1. The stack uses 27 weights per channel pair instead of 49, and it inserts two extra nonlinearities.

  2. Stride multiplies jump

    After a downsample, further 3×3s grow the field faster, in input pixels, because each step is a larger jump.

  3. Effective field can be smaller

    The theoretical RF is the support. If weights in the corners are tiny, the practical field is concentrated in the centre. Dilated convolutions grow RF without a stride, by inserting holes in the kernel.

WORKED EXAMPLE

The lab paints a square of side RF on a 15×15 canvas. Raise the number of 3×3 layers: 1 → RF 3, 2 → 5, 3 → 7. Then set stride to 2: the field jumps, and the jump readout doubles each layer.

Predict before you play: Two 3×3 layers at stride 2 — is RF 5 or something larger?

Layer 1: RF = 3, J = 2. Layer 2: RF = 3 + 2×2 = 7, J = 4. Larger than two stride-1 layers (RF 5), because the second kernel steps in input pixels of size 2.

WHAT TO LOOK FOR

Read the table under the grid. RF and jump should match the recurrence, not the picture’s crop.

07
TRANSLATION

Move the cat.
Move the features?

Complete ✓
IN ONE MINUTE

A convolution is translation equivariant: shift the input, and the feature map shifts by the same amount (when padding and cropping cooperate). It is not invariant. Invariance — “the cat is here, I do not care exactly where” — is assembled later, by pooling, by striding, and by the classifier.

f(TΔ x) = TΔ f(x)Equivariance of stride-1 convolution · T is a spatial shift

Read the commuting diagram. T_Δ slides the array. If you convolve then shift, you should get the same array as shift then convolve. Weight sharing is exactly what makes that true: the detector does not know it has moved. Fully connected layers do not commute with T_Δ, because each position has its own weights. Classification wants invariance at the end, not at the first layer — you still need to know that the ear is next to the eye.

7.1Name the property

Try it by hand

Stride-1 same-padded convolution is translation . After a 1-pixel shift of the input, the feature map shifts by pixel. A fully connected layer on flattened pixels is, in general, .

Show answer

Equivariant; 1; neither (not equivariant, and not invariant). Pooling is a step toward invariance, locally, as in 5.1.

THEORY · BEFORE THE VISUALIZATION

Shift the blob, read both maps

  1. Equivariance first

    The identity convolution with P = 1 copies the image. Shifting the copy is the same as copying the shift. That is the cleanest picture of the property.

  2. Boundaries still matter

    With P = 0, values fall off the edge and the equality can fail in the cropped frame. The lab uses same padding so the grids stay aligned.

  3. Then pool

    Max-pool after the shift is not always a shift of the pooled map. That mismatch is the beginning of invariance.

WORKED EXAMPLE

The lab’s blob sits near the left. Drag the shift. The right-hand conv map should be the left-hand conv map, slid. Compare a centre cell of the two pooled maps: they stay closer than the raw pixels did.

Predict before you play: If we shift by 2 pixels, does 2×2 max-pool stay identical?

Not necessarily. Two pixels is a whole pooling window, so the peaks move into a different output cell. A 1-pixel shift is the interesting case for local invariance.

WHAT TO LOOK FOR

Conv maps should travel together. If they do not, you are not looking at stride 1 with same padding.

08
ALEXNET · 2012

The network that
made the field look up.

Complete ✓
IN ONE MINUTE

Krizhevsky, Sutskever and Hinton’s AlexNet won ILSVRC 2012 by a large margin. Five convolutional layers, three fully connected, ReLU, overlapping pooling, dropout, and data augmentation. The first layer looks at 11×11 patches every 4 pixels.

(227 − 11)/4 + 1 = 55First map · 96 kernels · often quoted with 224 inputs and padding 2

Read the first layer. An 11×11 kernel on RGB is 11×11×3 = 363 weights per map, times 96 maps — still tiny next to the later fully connected layers, which hold most of AlexNet’s 60 million parameters. The large stride is an aggressive downsample: jump 4 already, RF 11. Everything after that reasons on a 55×55 (then smaller) grid, not on the raw 227.

8.1The stack, roughly

INPUT 227 × 227 × 3 CONV 11×11, S=4, 96 55 × 55 × 96 · ReLU · response norm · pool 3×3 S=2 CONV 5×5, 256 then pool CONV 3×3, 384 twice more at 384 and 256 · pool FC 4096 · FC 4096 · FC 1000 dropout on the 4096s · softmax
Try it by hand

First-layer Hout with 227, K = 11, S = 4, P = 0: . Weights in one 11×11 RGB kernel: . After that pool 3×3 stride 2, spatial size ≈ .

Show answer

55. 11×11×3 = 363. Pool: ⌊(55 − 3)/2⌋ + 1 = 27. (Some implementations use 27×27 after rounding conventions on 224-input variants.)

Key idea

AlexNet’s lessons that lasted: ReLU instead of saturating sigmoids, dropout on the large fully connected layers, heavy augmentation, and GPU training. Local response normalisation did not last. The fully connected tail is the parameter hog; VGG kept it, later nets replaced it with global average pooling.

Common mistake

“AlexNet is 8 learned layers, so it is small.” Depth is 8, but the last three layers are dense. Parameter count is not the same as convolutional depth. VGG-16 is deeper in convolution and even heavier in FC.

At the board What 2012 changed

Before AlexNet, the ILSVRC winner was typically a carefully engineered vision pipeline. After it, the default became: learn the features, use more data, use ReLU, regularise the dense layers. The architecture details were a snapshot. The training recipe was the revolution.

# First AlexNet-style conv in PyTorch (simplified)
nn.Conv2d(3, 96, kernel_size=11, stride=4, padding=0)
nn.ReLU(inplace=True)
nn.MaxPool2d(kernel_size=3, stride=2)
09
VGG · 2014

Only 3×3.
Just go deeper.

Complete ✓
IN ONE MINUTE

Simonyan and Zisserman replaced large kernels by stacks of 3×3 with stride 1 and padding 1. VGG-16 has 13 conv layers and 3 FC. Three 3×3 layers have the receptive field of one 7×7, with 27 weights instead of 49, and three ReLUs instead of one.

3 · (3 × 3) = 27   vs   7 × 7 = 49Per input/output channel pair · same RF = 7 at stride 1

Read the bargain. A 5×5 is two 3×3 (RF 5, 18 vs 25 weights). A 7×7 is three 3×3. VGG uses that substitution everywhere, and doubles the channel count after each max-pool (64-128-256-512-512). The spatial size of 224 is kept by P = 1 until a pool halves it. The design is a template: later residual nets kept 3×3 as the default atomic convolution.

9.1The cheap field of view

Try it by hand

Weights in three 3×3 vs one 7×7, one in-channel and one out-channel: vs . Two 3×3 vs one 5×5: vs . VGG same-padding P for K = 3: .

Show answer

27 vs 49, 18 vs 25, P = 1. The extra ReLUs are not in the weight count and are a further reason the stack can represent a more refined function on the same field.

THEORY · BEFORE THE VISUALIZATION

Deeper, narrower kernels

  1. Match the field

    n layers of 3×3 at stride 1 give RF = 1 + 2n, so n = 3 matches 7×7.

  2. Count the weights

    n × 9 versus (1+2n)². For n > 1 the stack is cheaper, and the gap widens.

  3. Pay in depth

    More layers are harder to train (vanishing signal — see the initialization sheet). VGG still trained with the 2014 recipe. Residual connections later made this bargain even better.

WORKED EXAMPLE

The lab bar chart is the 9n vs (2n+1)² comparison. Drag n. At n = 1 they tie at 9. At n = 3 you should recover 27 vs 49. AlexNet’s 11×11 first layer is the opposite choice: one wide view, immediately strided.

Predict before you play: At n = 4, is the large kernel 9×9?

Yes. RF = 1 + 8 = 9, weights 36 vs 81. The stack is less than half the price.

WHAT TO LOOK FOR

The teal bar should stay below the coral bar for n > 1. That is VGG’s entire kernel argument, in one picture.

1. Each valid 3×3 removes a one-pixel border (K − 1 = 2). VGG sets P = 1 so every pixel can be a centre, and uses pooling (or later, stride) when it actually wants to downsample. 2. Pooling only summarises responses that already exist. Without a kernel, there is no detector to summarise. 3. The stack composes three linear templates with ReLU between them, so the effective function on the 7×7 patch is piecewise linear and deeper, not a single inner product.
